# 查词视频附件

视频是查词回答的独立增值附件。入口只传递卡片、选中内容、所在句子，以及提交时捕获的后端与模型配置；主 AI 不等待附件，不将候选任务加入聊天历史、主请求队列、未读状态或完成通知。普通问答和析句不触发视频查询。

## 模块与查询

- `js/word_video.js`：独立服务客户端、缓存、取消、限时和附件控制器。
- `assets/word_video.css`：作用域样式。控制器将回答与附件放入同一外层容器，保留原回答 DOM 和 Markdown 渲染入口，流式更新不会重建视频。
- `subtitle_video_player.html`：创建卡片、停止、重试、会话切换和音频互斥的少量入口。可选模块缺失或初始化失败时继续原查词。
- `scripts/build_single-html.js`：将同一 JS、CSS 内联到单文件版。

1. 通过 `https://baidu-word-video-service-c7e3.netlify.app/v1/video` 匿名 GET 原词。
2. 只有正常 `ok:true, hasVideo:false` 才进入词形兜底。上游错误不会被视为无视频。
3. 可选地借用现有 COCA 模块中、对整个选中词生效的规则候选。只有唯一原形时直接尝试；候选有歧义、数据不可用或模块缺失时转入独立 AI。
4. POST 到该次查词的后端 `/`。继承 `provider`、`model` 的原有默认或手动选择语义；候选会话按路由和主会话隔离，并始终使用 `preserve:false`。每个路由复用专用会话，避免每个词都创建一个永不自动清理的后端会话。
5. 只发送 `query` 与最多 1200 字符的句子，不发送主问答的系统提示词、字幕全文或聊天记录。要求输出 `{"candidates":["word"]}`，最多三个，校验英文格式、长度并去重。只查接口真实返回的视频地址，模型不能提供视频 URL。

输入去首尾空格、合并空白、转小写及统一弯单引号；仅接受最多六词、80 字符的英文词条或短语，不截取长句作为检索词。视频及图片 URL 只接受无内嵌凭据的 HTTPS 地址，动态文案使用 `textContent`。

## 隔离和资源边界

- 元数据并发最多两个，候选 AI 并发最多一个，均为独立队列。相同词的在途元数据查询合并；取消一张卡片不会取消其他卡片共享的查询，最后一位等待者退出才中止共享请求。
- 元数据缓存最多 256 项，有视频一小时、正常无视频五分钟。候选缓存最多 128 项、十五分钟，并按路由、主会话、单词和句子区分。错误不进入无视频缓存。
- 单次元数据请求限时 22 秒、候选请求 20 秒，整张附件包含排队在内最多等待 45 秒。仅对单词视频显示重试，主问答可以继续执行。
- 卡片自身的执行代次和 DOM 归属用于判断迟到响应，独立于主 AI 当前活动项。主队列进入下一项后，已完成回答仍可收到自己的视频附件。
- 停止只取消当前卡片的未完成查询；重试 AI 会替换该卡片附件并取消旧请求。新对话、切换视频或字幕会取消旧查询，移除的卡片会释放视频资源。保留下来的历史附件暂停播放、仍可手动展开。
- 共用 AI 后端及模型额度会增加额外调用；只在原词与可用规则原形均未命中时请求候选。独立请求与状态不代表独占计算资源。

## 播放与交互

默认显示紧凑的封面、词条、时长与播放入口。仅在点击时设置 `<video src>`，不先获取 Blob 或保存视频文件。省略 `crossorigin`，因为目前百度 CDN 不提供相应 CORS 允许头。展开尺寸根据视频实际比例、附件宽度与 AI 消息区可用高度计算，并跟随窗口缩放；视频高度不超过回答滚动区域可见高度的 2/3（不含窗口标题栏和输入框）。横屏尽量利用宽度，竖屏收窄居中，避免固定高度产生大块空黑边。原生播放、进度和全屏控件保留，正片的隐藏控件样式仅作用于 `#video`。

讲解视频、正片和朗读相互暂停；结束讲解后由用户决定继续正片。收起窗口或页面不可见时暂停讲解，查询和主 AI 生成继续。视频键盘操作不会触发正片的播放速度快捷键，Esc 沿用原窗口与全屏规则。若只有音频轨道能够解码，会保留封面并显示提示。

用户展开视频时，仅在回答滚动区域内做必要的滚动，使附件标题、视频画面和底部控件完整可见，不调用聊天的贴底滚动。展开、收起期间短暂抑制浏览器滚动锚定，收起时保留标题所在位置。初次元数据加载引起尺寸变化时，只在用户仍停留于展开位置时补做定位；用户已经滚动离开则保留其阅读位置。

## 验证

```powershell
pnpm test
$env:SVP_PLAYWRIGHT = '已有 Playwright 包的绝对路径'
pnpm run test:word-video:browser
pnpm run test:queue:browser
pnpm run test:sentence:browser
```

本模块的日常浏览器检查只针对普通版源码；单文件版交由构建脚本自动生成，不手动维护生成文件。新浏览器检查使用隔离的 Chrome、项目内临时目录和仅监听 localhost 的静态测试服务器，AI、元数据和 CDN 都由测试样例控制，不调用真实模型或云端进度服务。运行前用本机 FFmpeg 在项目测试目录生成最小 H.264 样例：

```powershell
New-Item -ItemType Directory -Force test-results/word-video | Out-Null
ffmpeg -f lavfi -i "testsrc2=size=320x180:rate=5" -t 30 -c:v libx264 -preset ultrafast -pix_fmt yuv420p -movflags +faststart -y test-results/word-video/mock.mp4
ffmpeg -f lavfi -i "testsrc2=size=180x320:rate=5" -t 30 -c:v libx264 -preset ultrafast -pix_fmt yuv420p -movflags +faststart -y test-results/word-video/mock-portrait.mp4
```

单元检查覆盖缓存 TTL、同词共享与取消、上游失败、超时、URL 和 JSON 校验、独立候选会话、路由及句子缓存、并发与规则原形。浏览器检查覆盖：主 AI 先完成、下一条问答继续、视频迟到归属、直链按需播放、流式更新保持视频节点、朗读互斥、收起窗口、移动布局、附件重试和草稿保留、停止与新会话后的迟到响应，以及历史卡片展开完整可见、元数据延迟时尊重手动滚动、收起再展开后的定位。报告及截图位于已忽略的 `test-results/word-video/`。

布局回归还在开启正片隐藏控件的情况下，以真实鼠标操作横屏及竖屏视频的原生进度条，确认播放位置发生改变；同时检查大窗口、窄窗口和窗口缩放后的尺寸。媒体控件位于浏览器内部，不能仅以 `controls` 属性或伪元素的 `getComputedStyle` 值代替实际交互验证。

2026-10-30 的真实浏览器联调使用用户当轮指定的后端和 `kimi / kimi-for-coding-highspeed`：`beautifully` 无视频，独立候选请求返回可用词形后命中 `beautiful`；附件约 9.2 秒出现。主查词与候选各一次请求、会话 ID 不同，分别为 `preserve:true` 和 `false`。点击前没有媒体请求，点击后直链成功解码 1280×720 视频画面。该后端地址只用于隔离测试，未写入播放器默认配置；结果是单次样例，不代表长期耗时或任意词的覆盖率。
