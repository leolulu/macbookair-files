# 查词发音

## 范围与交互

- 使用浏览器 `speechSynthesis`，不嵌入模型、音频词库或第三方 SDK，不增加 AI 请求。
- 在原有一次查词提示词中约定：第 2 部分首次介绍目标词/核心短语时，在词语及其 Markdown 闭合符之后附加独立标记，例如 `**running**[[SPEAK:running]]`。普通加粗仅负责视觉强调，不触发按钮。
- 按钮只出现在查词回答中，与 COCA 候选、词形还原或收录情况无关。读显示词形，例如 `went` 就读 `went`。
- 标记内容须是纯英文字母、词内撇号/连字符及空格组成的短词组，最多 6 个词、80 个字符。每条回答最多处理 12 个有效格式引用，同一词只展示一次。忽略中文、数字、混合说明、链接、标题、代码和重复词；无标记时不添加按钮，不回退到加粗识别。
- 优先 en-US（含 en_US），其次其他英语音色；同类音色优先设备标为默认的音色。不指定平台专属名称，也不保证离线。
- 首次声音列表为空时在点击事件中直接用 en-US 请求朗读，同时监听 voiceschanged。接口不存在时保留解释正文；缺少英语音色或发音失败时提示，可再次点击重试。
- 点击朗读会暂停当前视频；不会自动恢复。连续点击停止上一段朗读。关闭对话窗、开启新对话、切换到后台或离开页面时停止朗读。

## 渲染与样式

`extract()` 先移除发音标记，保存词形及标记前的正文，再把清理后的文本交给现有 Markdown 渲染器。即使标记误写在加粗/斜体内部，标记也不参与 Markdown 解析。标记前缀同样经过 Markdown 解析后用于定位词语的具体出现位置，避免把按钮放到开场的同词上。词形必须紧邻标记；不匹配时省略按钮。

按钮由本地代码在 Markdown 消毒后创建，用 WeakMap 关联朗读词形；AI 提供的 HTML 不能直接创建可执行发音按钮。事件委托与朗读状态不依赖临时 DOM 节点，流式重绘后重新装饰并恢复按钮状态及键盘焦点。流式未闭合标记、无效标记在正常完成、停止、报错、重试和普通追问展示中使用同一清理逻辑；复制的正文没有内部标记。服务端仍按原有 preserve 会话机制保留模型原始回答，本次不改后端会话协议。

单色 SVG 随正文字号缩放，图标 1em，高度在既有 1.55 行高以内。透明点击区域向外扩展 3px，不参与排版。按钮没有文字内容，SVG 使用 inline 显示，避免 innerText 额外产生换行。按钮占少量水平空间，行尾空间不足时仍按正文正常换行。

## 第一版验证记录（加粗识别，2026-09-07）

- `pnpm.cmd test`：49 项通过，涵盖英语筛选、美国/其他英语音色回退、异步音色、连续点击、过期回调、引擎错误/超时、后台取消及不支持接口。
- `pnpm.cmd run build:single-html` 通过；普通 HTML 2 段、single HTML 15 段内联脚本语法检查通过。
- Chrome MCP 使用已配置模型：普通版实际查 `running costs`，single 版实际查 `Quidditch`，各一次 AI 请求生成可点击回答。
- 两个版本通过真实系统朗读的 start/end 事件验证，使用 Microsoft Mark / en-US。此处验证的是引擎完成事件，未对声音进行人工听辨。
- 用户随后在 Windows Chrome 中实际试听，确认发音效果良好。
- 真实连续点击验证上一段收到 interrupted，下一段正常结束；发音没有增加查词网络请求。
- 普通版用真实播放的 canvas 视频流验证点击后 video.paused 从 false 变为 true。
- 可控 SSE 验证 COCA 加载失败仍能为 went 和短语添加按钮，流式未闭合强调不误生成按钮，完成后添加，停止/错误/重试可用；普通追问不添加按钮。引擎故障另用注入错误验证按钮复位。
- 两个版本比较有/无按钮的浏览器选区文字与 innerText，均一致。260/360px 容器下，14/18/22px 字号的单行样本添加按钮后高度差均为 0；长句可以因按钮占宽而正常换行。

## 独立发音标记与多模型验证（2026-09-07）

通过 Chrome MCP，在普通版和 single HTML 的设置中实际切换下列模型。每个模型各查 `running costs`、`went`、`mother-in-law`，每轮开启新对话，保持同一提示词，未额外要求模型补标或重答。

| 模型设置值 | Provider | 完成回答 | 发音标记 / 按钮 |
| --- | --- | --- | --- |
| kimi-for-coding-highspeed | kimi | 3/3 | 4/4 |
| k3 | kimi | 3/3 | 3/3 |
| deepseek-ai/DeepSeek-V4-Flash-0731 | modelscope | 3/3 | 3/3 |
| deepseek-ai/DeepSeek-V4-Pro | modelscope | 3/3 | 3/3 |
| ZhipuAI/GLM-5.2 | modelscope | 3/3 | 3/3 |

- 共 15 次真实查词请求、15 条完成回答、16 个有效发音标记，均有对应按钮。三个测试类型覆盖词组中的核心词、过去式与原形对比、带连字符的复合词。
- 未观察到发音漏标、无效发音标记或普通英文加粗误生成按钮。比如 DeepSeek Pro 加粗 `run`、`running expenses` 等词源/搭配，但只给目标 `running` 加了发音标记。
- K3 的 mother-in-law 回答有一个 COCA 标记少了右括号。原有 COCA 清理逻辑会误删后续正文；已限制清理边界，防止吞掉正文或相邻 SPEAK 标记。重放该真实响应后，正文由异常时的 80 字符恢复到 1076 字符，发音正常，错误排名自然省略。不能据此认定错误是新增指令导致的；没有进行旧提示词的对照实验。
- 54 项单元测试及 single HTML 构建通过，普通版 2 段、single 版 15 段内联脚本语法检查通过。
- 两个版本各通过 16 个 DOM 样本，包括正确后缀、标记误嵌入加粗/斜体/引号、无加粗目标词、重复词、无效词形、普通强调，以及标题/代码/链接排除。移除按钮后 HTML 与无标记正文的 Markdown 渲染完全一致。
- 可控 SSE 验证半个标记、停止、报错、重试和普通追问清理；COCA 不可用时仍可生成独立发音按钮。正常样本与测试期间未观察到发音标记泄露。

这批小样本支持保留独立标记方案，不代表任何模型在所有输入上都能 100% 遵循。模型仍可能选错目标或漏标；前端不会根据普通加粗猜测补标。

Mac、iPhone/iPad、Android 的真实设备朗读与触摸体验尚待验证。当前不提供按语境指定音素或词典读音的能力，同形异音词由设备朗读引擎处理。
